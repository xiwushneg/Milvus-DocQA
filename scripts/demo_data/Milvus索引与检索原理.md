# Milvus 索引类型与检索原理

## 向量索引为什么必要

如果对每一个查询向量都与库中所有向量精确计算距离，复杂度随数据量线性增长，数据量一大延迟便无法接受。向量索引通过特殊的组织结构牺牲少量精度，换取几个数量级的检索加速，这类方法统称为近似最近邻搜索 ANN（Approximate Nearest Neighbor）。

## 主流索引类型

FLAT 是暴力精确检索，不做任何索引，适合小数据集或对精度要求极高的场合。IVF（倒排文件索引）先对全库向量做聚类，查询时只在最近的几个聚类中心对应分区内搜索，速度快但可能漏掉分区边界附近的近邻。HNSW（分层可导航小世界图）把向量组织成多层次的近邻图，查询从顶层稀疏图出发逐层下沉到精细层，兼顾高召回与低延迟，是生产环境最常用的 Milvus 索引类型，主流参数 M 控制每个节点的连接数、ef 控制搜索时的候选队列长度，参数越大越精确也越耗内存和延迟。DISKANN 将索引放到磁盘上，专为单机放不下内存的超大规模数据设计，用磁盘 IO 换内存容量。

选型经验：百万级以下数据、追求高召回低延迟，HNSW 是默认答案；数据量小且要求百分百精确，用 FLAT；内存受限的超大规模场景考虑 DISKANN。

## 相似度度量与标量过滤

Milvus 支持三种相似度度量：内积 IP、欧氏距离 L2 和余弦相似度 COSINE。文本嵌入向量归一化后，IP 与 COSINE 数学等价，文本检索普遍采用 COSINE。除向量相似度外，Milvus 还支持标量字段过滤：每个向量可以附带来源、页码、用户 ID 等结构化属性，查询时用布尔表达式先过滤再检索，这一特性让多租户隔离和权限控制可以直接在数据库层实现，也是 Milvus 相对于纯向量检索库的重要优势。
