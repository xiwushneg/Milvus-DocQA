# RAG、微调与长上下文的取舍

## 三条技术路线

让大模型掌握特定领域知识有三条常见路线。检索增强生成 RAG 把知识放在外部向量库，推理时检索相关片段拼进上下文；监督微调 SFT 用领域问答数据对模型参数做继续训练；长上下文方案则依赖模型超大的上下文窗口，把全部文档直接塞进提示词。

## RAG 的核心优势

RAG 最不可替代的能力是知识更新与溯源。文档变更只需重新入库，秒级生效，而微调一次动辄数小时且每次知识更新都要重训。RAG 的每个答案都来自可检索的具体片段，能给出引用出处，满足企业对可验证性的要求；微调把知识融进参数里，无法回答"这个结论出自哪份文件"。成本上，RAG 的主要开销是嵌入计算和向量存储，远低于微调所需的 GPU 训练资源。在抑制幻觉方面，RAG 把生成约束在检索到的证据范围内，配合引用机制可审计。

## 微调的适用边界

微调擅长改变模型的行为与风格，而不是注入事实知识。当需求是让模型学会特定的输出格式、语气规范、领域话术，或压缩提示词以降低推理成本时，微调是正确工具。用微调注入事实知识的问题在于：知识更新困难、容易过拟合、且无法保证"问了答得出"，模型是否记住某条知识只能靠事后测试，无法保证覆盖率。实践中成熟的做法是 RAG 管知识、微调管风格，两者互补而非互斥。

## 长上下文的代价

超长上下文模型可以直接把整本文档放进提示词，省去检索环节，但存在三重代价：一是推理成本随上下文长度增长，注意力的计算量是平方级；二是存在"中间迷失"现象，模型对超长上下文中部的信息利用率明显下降；三是每次请求都要传输全部文档，延迟与费用高企。对文档量超过几十页的场景，RAG 仍是性价比最高的方案。
