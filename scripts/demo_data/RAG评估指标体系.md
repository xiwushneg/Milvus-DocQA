# RAG 系统评估指标体系

## 为什么评估必不可少

没有评估的 RAG 优化全凭感觉：调整分块大小、更换嵌入模型、开关重排序，每一项改动到底有没有用无法回答。评估体系把系统效果变成可量化的数字，让每一次迭代都有数据依据，这是从演示项目到生产系统之间的分水岭。

## 检索侧指标

检索评估需要先构造评估集：每条样本包含一个问题和标准答案所在的片段位置（gold）。最常用的两个指标是召回率和平均倒数排名。Recall@K 衡量标准片段出现在检索结果前 K 条中的问题占比，回答"该找到的有没有找到"；MRR（Mean Reciprocal Rank，平均倒数排名）在命中基础上进一步考虑排名，标准片段排第一得 1 分、排第二得 0.5 分，以此类推后取平均，回答"找到的排得靠不靠前"。两个指标配合，既能看出漏召问题，也能看出排序质量问题。

## 生成侧指标

生成质量评估分为两个维度。忠实度（Faithfulness）衡量答案是否严格基于检索到的上下文、有没有编造内容，这是抑制幻觉的直接度量。答案相关性（Answer Relevance）衡量答案是否真正回应了用户的问题。自动化评估常用"用大模型评判大模型"（LLM as Judge）的方式：把问题、上下文、答案一起交给一个强模型，按评分标准打分；严谨的场景则辅以人工抽检校准。

## 评估驱动的迭代方法

正确的迭代流程是：先固定评估集和指标基线，然后每次只改动一个变量（如 chunk_size 从 500 改为 800），重跑评估对比指标变化，确认有效再合入。特别要注意评估集与知识库的匹配度——如果知识库只有几个片段，Recall@5 天然接近 100%，指标没有区分度；只有当知识库规模达到几十上百个块时，检索指标才能真实反映系统质量。
