# 从 RAG 到 Agent：大模型应用的架构演进

## 应用形态的三个阶段

大模型应用架构正在经历三个阶段的演进。第一阶段是纯生成：用户提问、模型作答，模型仅凭参数内知识回应。第二阶段是 RAG：外部知识通过检索注入上下文，模型从"凭记忆回答"变为"依据证据回答"。第三阶段是 Agent：模型不再只回答问题，而是规划步骤、调用工具、执行多步任务。

## Agent 的核心构成

一个 Agent 通常由四部分组成：作为"大脑"的大模型负责理解与决策；工具集把外部能力（检索、数据库查询、计算器、API 调用）封装成模型可调用的函数；规划机制决定多步任务的执行顺序，可以是模型自主推理（如 ReAct 模式的思考-行动-观察循环），也可以是预定义工作流；记忆机制保存任务状态与历史，支撑跨轮次的连续任务。在 ReAct 循环中，模型先思考"我需要什么信息"，再选择工具发起调用，观察返回结果后决定下一步，循环往复直到任务完成。

## RAG 在 Agent 时代的角色变化

进入 Agent 阶段，RAG 并没有被取代，而是降维成 Agent 工具箱中的一个工具。Agent 遇到需要知识的问题时调用检索工具，判断证据不足时可以改写查询再检索，甚至综合多个来源交叉验证——检索策略从固定流程变成模型的动态决策。这种"Agentic RAG"能处理单轮 RAG 无法应对的复杂任务，例如"对比两份合同的违约条款差异"，需要规划多次检索、结构化提取、对比综合。

## 演进的代价

能力升级伴随着成本升级：多步 Agent 的延迟与 token 消耗是单轮 RAG 的数倍，自主规划引入了不可控性，错误会沿着执行链传播。工程上应按需选择：能被固定流程解决的问题不需要 Agent 的自由度，Agent 的灵活性应留给真正开放式的任务。
