# 企业知识库落地的工程实践

## 从演示到生产的距离

一个能跑的 RAG 演示与一个企业可用的知识库系统之间，隔着工程化的鸿沟。生产系统必须在文档管理、权限、可观测性、持续运营四个方面补齐能力。

## 文档生命周期管理

企业文档是活的：合同会修订、制度会废止、新人会持续上传。系统需要完整的文档生命周期支持——上传、版本更新、删除与失效。删除文档时必须级联清理其在向量库中的所有分块，否则形成"幽灵引用"：被废止的条款仍会作为证据出现在答案里。版本更新应做到增量替换而不是全库重建，避免每次小改动都触发昂贵的全量嵌入。

## 可观测性

生产系统必须可观测。基础指标包括：问答量、检索命中率、各阶段延迟分布、大模型调用的 token 消耗与费用。更进一步，对低分答案建立人工反馈闭环：用户点"没有帮助"的问答记录进入待审队列，经人工标注后转化为评估集新样本，形成"线上反馈驱动评估集增长、评估集驱动参数调优"的正循环。

## 持续运营

知识库系统的效果不是上线时定格的，而是随运营演化的。定期用评估集回归测试，监控指标退化；文档库结构变化（如新增大类）后复查分块与检索策略的适配性；收集高频问题反哺文档建设——用户反复问而文档答不好的地方，往往说明源文档本身需要补充。RAG 项目的成功一半在技术选型，另一半在这些持续的运营机制。
