# 向量嵌入模型选型

## 嵌入模型在 RAG 中的作用

嵌入模型（Embedding Model）把文本映射成固定长度的稠密向量，向量之间的距离刻画了文本的语义相似度。在 RAG 系统中，嵌入模型决定了"语义上相关的段落能否在向量空间中彼此靠近"，是检索质量的根基。选错嵌入模型的代价无法通过下游调优弥补。

## 中文场景的主流选择

BAAI（智源实验室）发布的 BGE 系列是中文检索嵌入的事实标准之一。其中 bge-large-zh-v1.5 输出 1024 维向量，专门针对中文语义检索优化，在 C-MTEB 中文嵌入基准上名列前茅。更新一代的 bge-m3 是多语言、多功能模型：所谓 M3 是指 Multi-Lingual、Multi-Granularity、Multi-Function，它支持 100 多种语言、最长 8192 token 的输入，并且同时具备稠密检索、稀疏检索和多向量检索三种能力，输出 1024 维向量。对中文文档问答而言，bge-m3 在语义检索上的表现与 bge-large 相当，同时显著增强了对长文档和专业术语的表征能力。

OpenAI 的 text-embedding-3 系列效果优秀但属于闭源服务，数据需要出境；对数据敏感的企业私有文档场景，开源模型加自托管或国内托管 API 是更稳妥的选择。

## 向量维度与相似度度量

向量维度是精度与成本的平衡：维度越高表达能力越强，但存储和计算开销线性增长。常见的 768、1024 维是文本检索的主流选择。相似度度量方面，文本向量检索最常用余弦相似度 COSINE，它只关注方向而忽略模长，对文本长度不敏感；很多系统会将向量归一化后改用内积 IP，两者在归一化前提下数学等价。欧氏距离 L2 在文本场景较少使用。

## 托管 API 与本地部署的权衡

通过 SiliconFlow 这类托管平台调用 bge-m3，无需 GPU、按量计费、OpenAI 兼容协议一行配置即可接入，适合开发与中小规模生产。若要求完全的数据私有化，可以用 sentence-transformers 在本地 GPU 上加载同一模型，业务代码无需改动，只需切换配置中的 provider 字段。这种"接口不变、后端可换"的设计让嵌入层的私有化改造成本接近于零。
