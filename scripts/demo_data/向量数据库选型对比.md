# 向量数据库选型对比

## 选型的四个维度

评估一个向量数据库，通常看四个维度：检索性能（召回率与延迟）、数据管理能力（增删改查、持久化、备份恢复）、扩展性（单机到分布式的演进路径）、生态与工程友好度（客户端库、过滤能力、运维成本）。

## 主流方案对比

Milvus 是专门为向量检索构建的分布式数据库，支持多种索引类型与标量过滤，提供 Standalone 单机版与 Cluster 分布式版，两者 API 完全一致，小规模起步、大规模平滑升级，适合作为生产级知识库的底座。FAISS 是 Meta 开源的向量检索算法库，单机性能优秀，但它只是库而非数据库：数据管理、持久化、过滤都要自己实现，适合做算法实验或作为自研系统的内核。Chroma 是轻量级向量数据库，几行代码即可上手，适合原型验证，但分布式能力与大规模场景下的成熟度有限。Elasticsearch 以全文检索见长，8.x 版本加入向量检索能力，适合已有 ES 集群、BM25 需求为主的团队渐进引入向量能力；pgvector 则让 PostgreSQL 用户无需引入新组件即可获得向量检索，规模与性能上限低于专用向量数据库。

## 混合检索支持度

对文档问答这类场景，能否原生支持混合检索很关键。Milvus 支持在同一个集合中同时管理稠密向量与稀疏向量，并提供加权与 RRF 两种融合策略；也可以在应用层维护独立的 BM25 通道再自行融合，灵活性最高。ES 天然强在 BM25，向量检索相对是其插件能力。选型时应结合团队现状：从零构建的生产系统，Milvus 这类专用向量数据库是当前的主流选择。
