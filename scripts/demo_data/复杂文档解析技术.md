# 复杂文档解析技术

## 解析是 RAG 质量的第一道关口

 garbage in, garbage out——解析阶段丢失或错乱的信息，后续的检索与生成无论如何调优都无法挽回。企业文档远比纯文本复杂：多栏排版、表格、图片、页眉页脚、扫描件，每一类都是解析陷阱。

## PDF 解析的两条路线

基于规则路线以 PyMuPDF、pdfplumber 为代表，直接读取 PDF 内部的文本流与坐标信息，速度快、结果确定，对文本型 PDF 效果很好，但面对扫描件无能为力——扫描件本质是图片，内部根本没有文本流。基于视觉与 OCR 的路线对页面截图后用 OCR 引擎（或视觉大模型）识别文字，能处理扫描件与图片型 PDF，代价是速度慢、算力需求高，且 OCR 错误会向下游传播。工程上常用先探测后分流的策略：有文本流的走规则解析，纯图片页才走 OCR，兼顾质量与成本。

## 表格与版面结构

表格是重灾区：直接抽文本会把行列结构压扁成混乱的字符流，检索命中后大模型也无法解读。解决方案要么用支持表格结构还原的解析库输出结构化的行列数据，要么把表格转换成 Markdown 格式嵌入文本流，让大模型能按 Markdown 表格语法理解。页眉页脚、水印、页码这类重复性噪声应在解析阶段过滤，否则会产生大量低质碎块污染向量库。

## 元数据与溯源

解析时应为每个内容单元记录来源页码与标题层级，这些元数据随分块进入向量库，是引用溯源的数据基础。一个设计良好的解析器，输出的不是纯文本，而是带结构与出处的语义单元序列。
