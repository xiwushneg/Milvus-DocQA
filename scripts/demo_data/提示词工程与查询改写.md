# 提示词工程在 RAG 中的应用

## 提示词决定上下文的利用质量

同样的检索结果，不同的提示词写法会产生明显不同的答案质量。提示词工程（Prompt Engineering）在 RAG 中的作用，是把"检索到什么"转化为"模型怎么用"的关键一环。

## RAG 提示词的三要素

第一是角色与任务界定：明确告诉模型它是基于给定资料的问答助手，只依据提供的参考信息回答问题。第二是行为约束：资料能回答就依据资料作答并标注引用编号；资料不足或未涉及时，必须明确回答"根据现有资料无法回答"，禁止编造。这一条是抑制幻觉的第一道闸门。第三是输出格式约定：要求答案分点陈述、关键论断附带引用标记、控制在合理长度内，保证输出稳定可解析。

温度参数与提示词配合使用：问答类任务把 temperature 设为接近零的低值，减少模型的随机发挥，提高同一问题的答案一致性；生成温度越低，模型越倾向于选择概率最高的词，输出越保守确定。

## 迭代方法与常见陷阱

提示词的优化同样应该评估驱动：准备一组有标准答案的问题，每次修改提示词后批量重跑，对比答案质量，避免"感觉变好了"的主观判断。常见陷阱有三：一是指令堆砌过多，模型顾此失彼，约束应精简并按优先级排列；二是引用要求不具体，只说"给出引用"而不规定编号格式，输出会不稳定；三是忽略了上下文长度的预算，塞入过多候选块会稀释关键信息，还会增加成本和延迟，通常控制在五个块以内并按相关性排序。

## 进阶技巧

当单轮检索效果不佳时，可以在查询进入检索之前做改写：让大模型把口语化问题改写为检索友好的表达，或者一次生成多个改写版本分别检索后合并。这类查询改写技术与提示词工程结合，能进一步提升复杂问题的召回质量。
