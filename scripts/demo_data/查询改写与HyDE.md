# 查询改写与 HyDE 技术

## 为什么原始查询常常不适合检索

用户输入的查询与文档的表达方式往往存在系统性错位：查询是口语化、简短、带省略的，文档是书面化、完整、术语化的。向量检索把查询和文档映射到同一语义空间，能缓解但无法完全消除这种错位。查询改写技术族的目标，就是在检索之前把用户查询翻译成"更接近文档表达"的形式。

## 三种主流改写策略

查询扩展在原查询中补充同义术语与相关概念，扩大语义覆盖面，对一词多义的缩写尤其有效。多查询改写让大模型把一个查询改写成多个不同视角的版本，分别检索后用 RRF 融合，用多次召回的并集弥补单次召回的偶然性，代价是检索次数成倍增加。HyDE（Hypothetical Document Embeddings，假设性文档嵌入）思路更为激进：先让大模型凭空写一段"假想的答案文档"，再拿这段假设文档的向量去检索——因为假设答案与真实文档同属"答案文体"，向量空间中的距离比"问题文体对文档文体"近得多，实践中常能显著提升召回。假设文档中的事实错误无关紧要，要的只是它的语义轮廓。

## 与重排序的组合

查询改写解决"找不找得到"，重排序解决"排得靠不靠前"，两者作用于漏斗的不同层级，可以叠加使用。典型的增强链路是：查询改写或扩展 → 双路检索召回 → RRF 融合 → 交叉编码器精排 → 上下文选择。每一层都有成本，是否引入应由评估集数据决定：改写层对召回率提升明显，精排层对 MRR 提升明显，按业务短板对症下药。
