# 语义缓存与 RAG 性能优化

## 端到端延迟的构成

一次 RAG 问答的耗时由四段组成：查询向量化（几十毫秒）、检索（几十毫秒）、大模型生成（占大头，一至数秒）、以及可选的重排序。优化思路自然是"能不调大模型就不调，必须调就调得更快"。

## 语义缓存

语义缓存是性价比最高的优化：把历史问题与答案存起来，新问题进来先判断是否与缓存中的问题语义等价，等价则直接返回缓存答案。与精确缓存不同，语义缓存用嵌入相似度判断等价性——"Milvus 是什么"和"介绍一下 Milvus"字面不同但语义相同，精确缓存视为两次请求，语义缓存一次命中。实现要点是设置合理的相似度阈值：过高命中率低，过低则把不同问题误判为等价返回错误答案。缓存还应支持 TTL 与按知识库版本失效，文档更新后旧缓存必须作废。

## 生成阶段的加速

必须调用大模型时也有优化空间。流式输出不减少总耗时但显著改善体感——用户看到答案逐字出现而不是盯着空白等待。批处理把多个请求合并推理提高吞吐。上下文压缩减少送入模型的 token 数：对检索到的候选块做精简，去掉冗余词句，既提速又降费。此外，嵌入与生成模型支持 OpenAI 兼容协议，意味着任何时候都可以在本地 vLLM、Ollama 与云端托管之间切换，把延迟与成本控制在架构层面可调。

## 度量先行

所有优化都应建立在延迟度量之上：分别记录检索、重排、生成各阶段耗时，找出真正的瓶颈再对症下药，避免在几十毫秒的检索上过度优化而放任几秒的生成环节。
